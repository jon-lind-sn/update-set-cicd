Update Set CI/CD: the developer workflow

From a code change to a committed update set in production. GitHub Actions does the work between your steps.

Developer GitHub Actions ServiceNow instance Human approval
1. Author

Change the app

Edit the Fluent app and bump version in package.json. Each version is a new update set.

→

Open a pull request (PR)

A teammate reviews the code and the PR checks.

→

PR checks

A dry run using now-sdk build and generate proves the update set can be built from the source branch.

2. Deploy to TEST (on merge to main)

Generate update set

After PR approval and merge, now-sdk build and generate run on the main branch to create the update set file.

→

Import to TEST

import uploads the file, previews it, and commits it on TEST. A preview problem stops the run and commits nothing.

3. Promote to PROD (run by hand)

Start promotion

Run the promotion workflow and enter the update set name from the TEST run summary.

→

Approve

A reviewer approves the production environment in GitHub.

→

Move to PROD

move copies the update set TEST committed, so PROD gets the same record as a manual pull from TEST.

Rejecting the approval keeps the change out of PROD. Merges never wait on a promotion.
